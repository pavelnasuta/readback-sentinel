# Технический регламент локального audio-QC

**Версия:** 3.0 / ядро v0.4.0

**Статус:** experimental, candidate-only

**Исполняемый код:** `scripts/run_qc.py` и модули `audiobook_qc/`

## 1. Контракт безопасности

1. Машинный сигнал — кандидат, не установленная ошибка диктора.
2. Анализ создаёт только reviewer-facing артефакты.
3. Narrator-facing DOCX/CSV создаются отдельным confirmation mode из просмотренного report snapshot, без повторного ASR.
4. `ALIGNMENT_FAILED` блокирует text diff.
5. Неоткалиброванные признаки не превращаются в положительные или отрицательные вердикты.
6. Каждый прогон изолирован и имеет manifest `STARTED`, затем `COMPLETED` либо `FAILED`.

## 2. Входы

| Роль | Форматы | Обязательность |
|---|---|---|
| `audio` | WAV/MP3/FLAC | обязательно |
| `printed_text` | PDF/DOCX/UTF-8 TXT | обязательно |
| `glossary` | JSON array `{term, transcription?, notes?}` | опционально |
| `reference` | — | не реализовано; CLI отклоняет параметр |

Перед тяжёлой обработкой проверяются пути, конфиги, tag и совместность `--review-report`/`--confirmed-flags`.

## 3. Analysis mode

### 3.1 Provenance и lifecycle

- Создаётся уникальный `run_id` и `analysis_<tag>_<run_id>/`.
- Manifest schema 2 записывается атомарно в `STARTED` до ASR.
- Он содержит только имена, размеры и SHA-256 входов, версии/хеши конфигов, модель и язык — без копирования исходного содержимого.
- Любое перехваченное исключение переводит manifest в `FAILED` и перечисляет только файлы этой попытки.
- Успех перечисляет обязательные созданные артефакты текущей попытки.

Жёсткое убийство процесса может оставить `STARTED`; это честный незавершённый статус, не успех.

### 3.2 Извлечение текста

- PDF: PyMuPDF `page.get_text()`.
- DOCX: обычные абзацы и все ячейки таблиц.
- TXT: UTF-8.

### 3.3 ASR

`faster-whisper`, CPU/int8, `beam_size=5`, VAD `min_silence_duration_ms=500`, выбранный language. Выход: `{start,end,text,avg_logprob}`. ASR не является ground truth.

### 3.4 Нормализация

- NFKC, lower-case, `ё→е`, Unicode-дефисы;
- пунктуация и перенос строки ограничивают числовые группы;
- валидные составные кардинальные числа до 999 объединяются (`двести один→201`);
- перечисления и повторные разряды не складываются (`один, два, три→1 2 3`; `двести двести→200 200`).

### 3.5 Alignment

Для каждого размера anchor из YAML находятся **все** вхождения начального и конечного якоря в печатном тексте. Кандидаты сравниваются только по точному диапазону `start … end+anchor_size`.

- единственный лучший диапазон → `ALIGNED`;
- равные лучшие диапазоны, неверный порядок или отсутствие границ → `ALIGNMENT_FAILED`;
- поисковый контекст после конечного anchor не входит в diff.

### 3.6 Text diff и таймкоды

`SequenceMatcher(..., autojunk=False)` работает только по найденному окну. Replace/insert/delete создают `REVIEW`-кандидаты. ASR confidence сохраняется как evidence, но не повышает severity и не доказывает источник ошибки.

Токены каждого ASR-сегмента образуют диапазон provenance. Флаг получает начало первого и конец последнего затронутого сегмента. Вставка в источник без ASR-токена привязывается к ближайшей известной границе, а не безусловно к `00:00`.

### 3.7 Глоссарий

Поиск идёт по нормализованным целым одно- и многословным вариантам, а не подстрокам. Точная `term` или `transcription` допустима. Только близкое написание с тем же числом слов, совпадающими начальными буквами и длинами токенов создаёт `GLOSSARY_REVIEW` на таймкоде конкретного сегмента. Отсутствие термина во всём фрагменте само по себе не флагается: термин мог не встречаться в прочитанном отрывке.

Это строковая эвристика для переслушки, не фонетический анализ произношения.

### 3.8 Акустика

1. Файл загружается в исходной частоте и с исходными каналами.
2. Пик и число сэмплов выше `clip_sample_amplitude` измеряются **до** downmix/resample.
3. Для остальных диагностик строится mono/16 kHz поток.
4. RMS охватывает и последнее неполное окно.
5. Тихие окна объединяются в интервалы; внутренние интервалы длиннее настроенного порога создают `ANOMALOUS_PAUSE` REVIEW.
6. `SILENT_AUDIO` не скрывает нативный `CLIPPING`, если каналы погасили друг друга при downmix.

`amplitude_percentile_ratio_db` хранится только как диагностическое P95/P10. Поля `snr` и `noise_to_signal` равны `null`, `noise_assessment=NOT_CALIBRATED`; автоматический `NOISE` не формируется.

### 3.9 Просодия

pYIN считается чанками, чтобы не создавать одну большую внутреннюю матрицу на весь файл. Используются P5/P95 F0, медиана, voiced percentage и самая длинная непрерывная voiced-duration.

- нет voiced frames → `NOT_EVALUATED`, `monotony_flag=null`;
- самая длинная непрерывная voiced-область не превышает настроенный минимум → `INSUFFICIENT_EVIDENCE`, `monotony_flag=null`;
- только при достаточной непрерывной voiced-области порог может создать `REVIEW`, не утверждение о художественном качестве;
- отсутствие кандидата → только diagnostic status, не «выразительно»;
- график масштабирует ось F0 по реальным данным, поэтому контур выше 400 Гц не обрезается;
- готовые серии передаются в exporter: pYIN второй раз не запускается.

### 3.10 Report snapshot

Report schema 3 содержит input hashes, config hashes, model/language, flags и `review_binding`. Все flag IDs валидируются как непустые и уникальные; prosody использует отдельный namespace. Binding — SHA-256 канонического набора этих полей. Он исключает volatile run timestamps, поэтому связывает именно детекторный снимок.

Предварительные артефакты:

- `report_<tag>.json/.pdf`;
- `triage_<tag>.docx`;
- `triage_markers_<tag>.csv` с ненулевой Duration для диапазонных кандидатов;
- transcript JSON/TXT;
- prosody PNG.

PDF экранирует имена и строки флагов перед передачей ReportLab.

## 4. Confirmation mode

Требуются одновременно `--review-report` и `--confirmed-flags`. Confirmation JSON:

```json
{
  "review_binding": "<из просмотренного report>",
  "confirmed_flag_ids": ["flag_0000"]
}
```

Проверяется:

1. status предварительного report;
2. SHA-256 текущих audio/text/glossary против report;
3. пересчитанный `review_binding` против содержимого report;
4. binding confirmation против report;
5. уникальность и существование ID;
6. severity каждого ID входит в `CRITICAL|REVIEW`.

ASR/акустика/просодия не запускаются. Manifest confirmation-попытки наследует модель, язык, версии и хеши конфигурации из связанного просмотренного report, а не из CLI-defaults. В уникальной `confirmation_<tag>_<run_id>/` создаются только подтверждённые `перепись_<tag>.docx`, `audition_markers_<tag>.csv` и manifest.

## 5. Что не реализовано и не доказано

- precision/recall/FPR на представительском размеченном наборе;
- валидированный noise/SNR detector;
- объективная оценка художественной выразительности;
- word-level ASR timestamps;
- семантическая сверка и сравнение с демкой;
- пакетная очередь, Sheets/облака/Nextcloud/Telegram и Ubuntu service;
- delta-recheck исправленных фрагментов.

До eval все кандидаты проходят human gate. `COMPLETED` означает техническое завершение попытки, не принятие работы.
