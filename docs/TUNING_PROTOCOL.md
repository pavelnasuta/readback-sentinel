# Протокол тюнинга

Цель тюнинга — не максимальное число флагов, а меньше ложной работы при сохранении действительно важных ошибок.

## Что делает система перед вопросами человеку

После каждого прогона она группирует кандидаты по категории, уверенности, диктору, длительности и причине срабатывания. Затем готовит короткую карточку: аудиофрагмент, эталонная фраза, ASR-текст, таймкод и предложенная категория.

## Что отвечает куратор

Для каждой отобранной карточки достаточно одного решения:

- `CONFIRMED` — ошибка диктора/записи реальна;
- `REJECTED_AS_ASR` — диктор прочитал верно, ошиблась машина;
- `REJECTED_ALLOWED` — расхождение допустимо стандартом;
- `RECLASSIFIED` — проблема реальна, но категория другая;
- `UNCLEAR` — требуется ещё одно прослушивание.

Если решение `RECLASSIFIED`, дополнительно выбирается категория: текст, имя/термин, число/дата, технический дефект, пауза, интонация, другое.

## Вопросы, которые Hermes должен задавать по очереди

Не задавать большую анкету. Один цикл = одна группа проблем.

1. **Правило:** «Считается ли это браком по вашему стандарту?»
2. **Риск:** «Хуже пропустить такую ошибку или зря отправить диктора на перезапись?»
3. **Варианты:** «Какие произношения/написания допустимы?»
4. **Контекст:** «Термин обязан быть именно в этом фрагменте или он относится к всей книге?»
5. **Эталон:** «Нужна ли ссылка на согласованную демку для оценки темпа/подачи?»
6. **Подтверждение:** «Сколько из показанных кандидатов реально были ошибками?»

После ответов Hermes формирует не изменение, а **предложение тюнинга**: гипотеза, какие пороги/правила затрагиваются, прогноз риска, тестовые примеры и критерий отмены. Код меняется только после одобрения предложения.

## Метрики

Считаются отдельно для каждой категории и версии:

- `precision` = подтверждённые системой ошибки / все флаги системы;
- `recall` = подтверждённые системой ошибки / все ошибки в ручной разметке;
- `false-positive rate` = ложные флаги / все флаги;
- `triage_minutes_per_audio_hour`;
- доля файлов, вернувшихся на повторную перезапись;
- доля успешно закрытых замечаний после дельта-перепроверки.

Одна общая метрика запрещена: хорошая работа на клиппинге не компенсирует ложные претензии по именам.

## Стартовая стратегия

Первые 6–8 недель:

- ручной триаж всех высокорисковых кандидатов;
- проверка не менее 20% аудио в стратифицированной выборке;
- обязательная проверка имён, дат, чисел и терминов;
- ни один флаг не уходит диктору без подтверждения;
- каждую неделю — один отчёт по качеству кандидатов, не больше одной новой гипотезы за раз.

Снижение ручной выборки возможно только после нескольких стабильных оценочных прогонов по agreed метрикам.
